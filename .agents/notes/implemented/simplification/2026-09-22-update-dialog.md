# Agent Note: 检查更新改回弹窗并打开官网

Status: implemented

## Problem

关于页的应用内更新卡片把 GitHub Releases 请求失败当成「已是最新」。未登录接口每小时 60 次，超限返回 403 时，已安装的 0.3.4 一直显示当前版本，用户看不到 0.3.5。应用内下载安装也让「去哪更新」比打开官网更绕。

## Decision

手动检查仍用系统对话框。有新版本时，「前往官网下载」打开 `https://tether-code.xyz/`。版本号来自 `https://github.com/tt-11-dd/tether-ai/releases/latest` 的 302 `Location`（`/releases/tag/vX.Y.Z`），用 Node `fetch` 停在跳转上读，不请求 `api.github.com`。Electron `net.fetch` 跟跳转后拿不到最终地址，会误报检查失败。页面不是 2xx，或最终地址里没有版本号，都算检查失败；手动检查失败弹出失败对话框，同样可以打开官网。

启动时发现新版本，在窗口中央弹出遮罩对话框，点「前往官网下载」或「稍后」才会关掉。`pnpm dev` 也会查一次，所以本地版本低于已发布版本时能看到这个对话框。已是最新或请求失败时，启动检查保持沉默。应用内下载、安装和关于页卡片已去掉。

## Alternatives considered

只修 403 的判定，保留应用内下载。卡片仍要解释下载、安装和平台差异，而用户要的是去官网。

失败时仍显示「已是最新」，另加一行说明。用户已经把这行当成「没有新版本」。

启动时只留一条几秒就消失的 toast，并让用户自己去「设置 → 关于」。这条提示可以被忽略，也到不了官网。

## Consequences

手动检查总会有一个对话框：已是最新、发现新版本，或检查失败。新版本和失败都可以打开官网。已安装的 0.3.4 和已发布的 0.3.5 仍是旧卡片，要再发一版才会换成对话框。
